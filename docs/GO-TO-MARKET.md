# Fumi — 販売戦略と商用化ロードマップ

対象市場: 海外（英語圏中心）＋日本。課金形態: **買い切りライセンス**。

このドキュメントは「どこで・いくらで売るか」と「売れる状態にするまでの残作業」を一元管理する。

---

## 1. 販路の決定

**自社サイト直販 ＋ Merchant of Record（Lemon Squeezy または Paddle）を第一チャネルとする。**

| 候補 | 採否 | 理由 |
|---|---|---|
| 自社サイト直販（MoR 経由） | ✅ 第一 | MoR が海外の VAT / 消費税の徴収・納付を代行。個人開発者が世界に売る最短手。手数料は概ね売上の5%前後（要最新確認）。Win/Mac/Linux 全対応で TAM 最大 |
| Mac App Store | 後続 | Apple が決済・信頼・更新を代行し発見性も高い。ただし手数料 15–30%、サンドボックスが localhost OAuth サーバと衝突するため要改修。Mac 限定 |
| Setapp（サブスク型バンドル） | 検討 | 買い切り方針と相性が悪い。将来の追加収益として保留 |
| 直販のみ（MoR なし / Stripe 直） | ✗ | 海外消費税を自前処理する負担が大きい |

**結論**: まず MoR 直販で世界に出す → 軌道に乗ったら MAS を追加チャネルとして並行。

## 2. 価格の決定

- **買い切り 1 ライセンス $29–49**（海外インディー Mac アプリ相場）。初期は $39 を起点に検証。
- **メジャーバージョンアップは有償**（例: v2 で割引アップグレード）。継続的な開発原資を確保。
- AI 機能は **BYO-key**（ユーザー自身の API キー）。サーバ側 AI コストがゼロなので買い切りで黒字構造が成立する。
- 為替・購買力に応じた地域別価格（PPP ディスカウント）は MoR の機能で後追い可能。

## 3. 売上を最大化する一手 = Google OAuth 審査

最大のボトルネックは機能ではなく **Google OAuth の検証（restricted scope）**。

- 現状の利用スコープ: `gmail.modify` / `gmail.compose` / `gmail.send` / `calendar` ＝ **restricted scope**。
- 未審査だと「未確認アプリ」警告画面 ＋ **100 ユーザー上限**で、そもそもスケールしない＝売上が頭打ち。
- 審査には年次 **CASA（Cloud Application Security Assessment）Tier 2** セキュリティ監査が必要（費用はベンダーにより数百〜数千ドル/年、要見積取得）。加えてプライバシーポリシー、ホームページ、デモ動画、ドメイン所有確認が必須。
- → **埋め込み OAuth でワンクリック化（実装済み）＋ 審査通過**が実質の売上アンロック。審査は数週間〜かかるため最優先で着手する。

## 5. 既知の技術的注意点

- **MAS サンドボックスと OAuth**: 現在の認証は Rust 側の localhost コールバックサーバ（ポート 17248–17251）に依存。MAS のサンドボックスでは外部ポート listen が制限されるため、MAS 版は ASWebAuthenticationSession 等への再設計が必要。直販版は現行方式で問題ない。
- **OAuth クライアントシークレット**: 「Desktop app」クライアント種別のシークレットは Google の方針上「機密ではない」扱いで、バイナリ同梱が前提（`.env` → ビルド時埋め込み）。
- **i18n の残移行**: 文字列はまだ大半がハードコード英語。基盤と移行パターンは確立済みなので、機械的な置換作業として段階的に進められる。
